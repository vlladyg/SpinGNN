## What We Discovered About Rank Reduction

### Approach Tested: Rebuild Architecture + Load Compressed Cores

**Method**:
1. Load full-rank model
2. Apply SVD to compress TT-cores
3. Create **new** model with reduced-rank architecture
4. Transfer all weights except TT-cores
5. Load compressed cores
6. Evaluate

**Results**:
- ✓ Full rank [16,16,16]: Works perfectly
- ❌ Reduced rank [14,14,14]: Dimension mismatch

### Root Cause Analysis

The error occurs at line 206 in `_etn_als_opt.py`:

```python
u_out[:, slice, :] = torch.einsum('ij,Nmj->Nmi', 
                                    self.cores[-1][i].squeeze(-1), 
                                    F[:, slice, :])
# Error: u_out has shape [..., 14] but einsum output has shape [..., 16]
```

**Why This Happens**:

1. **`u_out` allocation** (line 188):
   ```python
   u_out = torch.zeros((F.shape[0], F.shape[1], self.N_rank_ett[-1]), ...)
   ```
   Uses reduced rank: `self.N_rank_ett[-1]` = 14 ✓

2. **`F` (NODE_FEATURES_F) generation**:
   - Generated by embedding layers BEFORE the ETN module
   - These layers were trained with rank-16 architecture
   - Output dimensions: `[..., 16]` (not 14!)

3. **Dimension mismatch**:
   - The einsum contracts the last dimension of cores with F
   - Cores have rank-14, but F has rank-16 features
   - Result: incompatible tensor shapes

### The Fundamental Problem: Architectural Coupling

The ETN model is **deeply integrated** into the full architecture:

```
Input → SphericalHarmonics → RadialEmbedding → Linear(→rank-16) 
     → ETN(rank-16) → Output
```

When we change ETN ranks, we break the dimensional flow because:
- Pre-ETN layers produce rank-16 outputs
- ETN expects rank-14 inputs
- Post-ETN layers expect rank-16 inputs

**To fix this, we would need to**:
1. Retrain ALL embedding layers for rank-14
2. Retrain ALL linear projections
3. Retrain the output head
4. Essentially: **retrain the entire model**

## Conclusions

### What Works

✓ **SVD Orthogonalization (Full Rank)**
- Use: `rl_orthogonal_svd(cores, R, instr, target_ranks=None)`
- Purpose: Numerical stability, same as QR
- Effect: No accuracy change, no compression

✓ **SVD Core Compression (Standalone)**
- Can compress individual TT-cores successfully
- Useful for: initialization, analysis, research

### What Doesn't Work

❌ **Post-Training Compression via Core Swapping**
- Cannot reduce ranks after training
- Model architecture is too coupled
- Requires full model retraining

### Recommended Approaches

#### Option 1: Train with Reduced Rank from Start (RECOMMENDED)

```yaml
# config.yaml
N_rank_ett: [8, 8, 8]  # Set target rank before training
```

**Advantages**:
- Clean, architecturally consistent
- Full optimization for reduced rank
- Best accuracy for given rank

**Steps**:
1. Modify config with target rank
2. Train model from scratch (or fine-tune from compressed initialization)
3. Evaluate compression vs accuracy trade-off

#### Option 2: SVD-Initialized Training

```python
# 1. Load full-rank model
full_model = load_model("best_model_rank16.pth")

# 2. Compress cores via SVD
cores_compressed = compress_cores_svd(full_model, target_rank=[8,8,8])

# 3. Create new rank-8 model
model_rank8 = create_model(rank=[8,8,8])

# 4. Initialize with compressed cores
model_rank8.load_cores(cores_compressed)

# 5. Fine-tune
train(model_rank8, epochs=10)
```

**Advantages**:
- Faster convergence (good initialization)
- May achieve better final accuracy
- Leverages knowledge from full-rank model

#### Option 3: Progressive Rank Reduction During Training

Train with gradually reducing ranks:
- Epochs 0-50: rank [16,16,16]
- Epochs 51-70: rank [12,12,12] (transfer + fine-tune)
- Epochs 71-90: rank [8,8,8] (transfer + fine-tune)

**Advantages**:
- Smooth transition
- Potentially better accuracy retention
- Research-oriented approach
